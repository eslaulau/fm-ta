# FM27 引擎红利四后卫｜跨版本指令决策台账

本文件是 V1.x 及后续版本的**跨代配置沿革与效果证据总账**。它与 `ITERATION_LOG.md` 分工：

- `ITERATION_LOG.md`：按版本叙述每一代为什么升级、做了什么整体设计。
- 本文件：按同一条配置/指令追踪它从哪一代开始、后续如何变化、哪些证据支持保留、哪些仍待验证。
- 各代 `*.json` recipe、原生 `.fmf` 和 same-run report：是配置与构建身份的最终事实来源；本表不能覆盖原始配方。

**核心原则：下一代不只是复制上一代战术，而是继承此前所有版本的决策证据。**

---

## 1. 记录规则

### 1.1 每条记录的唯一身份

PI 必须按以下组合区分，不得把同名指令跨位置、跨阶段、跨角色合并：

`阶段(IP/OOP) + 位置 + 原生角色 + 职责 + PI组 + PI值`

例如，DCR 无球中后卫的“较少地逼抢”与 DL 无球逼抢边后卫的“更多地逼抢”是两条不同记录。角色、位置或职责变化时，应创建新的配置身份，旧身份保留历史记录。

TI 按“全队/共享 TI + TI 组”建立身份。阵型/结构作为独立的协同配置记录，不能硬拆成某一条 PI 的效果。

### 1.2 结论状态必须区分

| 状态 | 含义 |
|---|---|
| **保留（观察支持）** | 多个可比样本或持续表现支持继续使用；仍不自动等于单项因果证明 |
| **暂时保留（待验证）** | 目前没有足够反证，且与整体方案协同；尚无独立效果证据 |
| **条件保留** | 只在指定阶段、位置、角色、职责、球员条件或对手情境下保留 |
| **替换/退役** | 当前版本不再使用；保留历史，不把它删除出沿革 |
| **待验证** | 新改动尚无 D5 比赛样本 |
| **证据不足/不可判断** | 字段缺失、身份/角色码覆盖不足、数据质量或比较协议不允许判断 |

“保留”不代表永久锁定；“退役”不代表该设置在任何阵容或结构中都无效。不得把“没有证据”写成“已经证明无效”。

### 1.3 证据强度与因果边界

每项结论同时记录证据等级：

- **直接配置证据**：recipe/FMF 回读确认该设置确实存在。
- **赛季观察证据**：用户确认版本映射后的球队/球员数据。
- **关联证据**：版本、主客场、胜平负分组间存在可复核差异。
- **机制/外部证据**：当前 build 的官方说明或外部测试；标明 build、日期和测试协议。
- **因果证据**：只有同一存档状态、可复现 seed 或受控对照才可提高因果判断。不同存档重新模拟及不同版本共同赛程只能作为描述性证据。

若角色码覆盖不足，不得将球队总成绩归因到单个角色/PI。若多项配置同时改变，必须优先评价“组合/结构层级”，不要假装分离出单项贡献。

### 1.4 每次新报告必须执行

1. 确认报告由用户明确映射到哪个版本。
2. 对比该版本与父版本的完整 recipe，列出新增、改变、保留和删除的配置。
3. 按本台账找到对应配置身份，更新该行的观察、状态、证据等级和下一步验证目标。
4. 对本轮同时变化的 PI/TI/结构建立“协同组”记录。
5. 未经本队 D5 数据验证的最新改动，一律保持“待验证”。
6. 犯规、黄牌、红牌不得进入效果评价或去留决策。

## 5. 去留决策记录模板

每轮新报告后，将下面模板追加一行或一组行：

| 报告/版本 | 配置 ID | 实际观察 | 正向证据 | 负向/代价 | 数据与归因限制 | 决策状态 | 保留/替换理由 | 下次验证指标 |
|---|---|---|---|---|---|---|---|---|
| Exporter Run ... | ... | ... | ... | ... | ... | ... | ... | ... |

效果评价时至少分开记录：

- 结果：胜平负、积分、进球、失球。
- 进攻：xG/NPxG、射门、射正、绝佳机会、禁区威胁、传中及成功率、推进传球。
- 防守：对手 xG/xGA、射门、射正、绝佳机会、进入前场三区/推进。
- 转换：丢球后被推进、夺回球权、反击接应与纵深。
- 球员：分钟、每90产量、身份覆盖、位置/role_code 可信度。
- 环境：FM27 build、对手强度、主客场、赛事范围、样本量、存档哈希/重放条件。

纪律数据一律不进入该表的战术评价字段。

## 6. 每代必须新增的“保留 / 替换 / 待验证”摘要

每代发布新 FMF 前，必须输出：

1. **继承保留：** 哪些配置因既有证据而继续使用，引用台账 ID。
2. **暂时保留：** 哪些配置尚未单独验证，但作为整体协同的一部分保留。
3. **本轮替换/退役：** 哪些设置被改掉，为什么；旧值与旧证据不能删除。
4. **新增待验证：** 本代新增哪些 PI/TI/角色/职责/结构，以及 D5 应观察什么。
5. **尚不可判断：** 哪些配置由于角色码、身份或字段语义覆盖不足，不应作结论。
6. **组合层级：** 多个字段共同改变时，明确评价它们组成的整体结构，而不是分摊为单项功劳。

任何未在台账中的关键配置变化都视为研发记录不完整；不得只生成新配方而跳过决策历史。

## 7. 后续维护

- 本文件作为唯一跨版本指令决策台账；`ITERATION_LOG.md` 继续保留逐代完整叙事。
- 每次 D5 赛季复盘后更新本文件；每次 D0/D1 设计时先读取本文件，再决定继承、替换或试验。
- 若新版本修改某条已存在配置，必须更新其沿革行，并在去留记录中说明旧值为什么被替换。
- 若版本不再使用某条 PI/TI，标记为“替换/退役”，不得删掉该记录。
- 若只存在系统级成绩而缺乏角色级数据，只能对结构/组合层级给判断；单项行保持“暂时保留”或“证据不足/不可判断”。
