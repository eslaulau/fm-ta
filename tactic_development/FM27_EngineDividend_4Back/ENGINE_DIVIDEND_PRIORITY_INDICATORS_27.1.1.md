# FM27 引擎红利优先参考指标｜27.1.1

- 资料性质：用户明确指定的高优先级外部机制假设与后续研发参考。
- 适用版本：FM27 27.1.0 / 27.1.1；具体结论必须按当前游戏 build 复核。
- 状态：**优先验证假设，不等于本队已验证有效，也不自动成为强制配置。**
- 项目硬约束：IP 有球阶段后场 DL、DCL、DCR、DR 四个位置槽各一次；其余 IP 结构开放，OOP 结构完全开放。不得把本文件误读为固定 4-2-3-1，也不得因 OOP 五后卫候选而改变 IP 四后场硬约束。
- 研发目标及D0-D5流程仍以 `PROJECT_RULES.md`、`PPG_TARGET_POLICY.json` 和本项目权威决策总账为准。

## 1. 无球防线高低错位与无锋五后卫

### 1.1 高位逼抢遭遇线 + 大幅后撤后防线
- 用户提供的机制判断：27.1.0 后，高位逼抢遭遇线与大幅后撤后防线的组合仍是高优先级防守底层；前场主动压迫对手出球，后防线收缩保护身后空间。
- 预期收益：减少直塞打身后和禁区内高质量机会，压低对手禁区内 xGA。
- 验证指标：对手禁区内 xGA、总 xGA、对手禁区触球、直塞成功/威胁、身后球形成的射门、对手绝佳机会；主客场分别统计。
- 风险/边界：高位遭遇线可能在前后场之间形成空间；后撤防线可能让对手获得禁区前沿控球和远射。不能只凭总 xGA 判断成功。

### 1.2 无锋阵与无球五后卫
- 用户提供的机制判断：纯模拟测试中，OOP 五后卫（双翼卫 + 三中卫）与前场前腰/影锋顶在最前面的无锋结构具有明显优势。
- 预期收益：OOP 增加禁区防守人数，前场利用无锋跑位和肋部空当。
- 验证指标：OOP实际落位、对手禁区内 xGA、对手绝佳机会、肋部被穿透次数、反击出口、前场无锋球员的触球/跑位/射门/关键传球。
- 设计约束：优先研究如何在 IP 四后场硬约束下实现 OOP 五后卫；需要允许球员跨阶段换位时，必须核对 11 槽/22 阶段原生角色映射和合法性。不得假定角色名称本身就保证目标站位。

## 2. 后腰无球锁位

- 用户提供的机制判断：后腰与拖后组织核心（DLP）存在过度前插倾向，可能在攻防转换时造成防线身前真空。
- 四后卫结构优先测试：回撤型后腰（Dropping Defensive Midfielder）或屏障型后腰（Screening Defensive Midfielder）。
- 五后卫结构优先测试：边路补位型后腰（Wide Covering Defensive Midfielder）。
- 预期收益：保持后腰位于防线身前，稳定 Rest Defence，保护中路与半空间。
- 验证指标：丢失球权瞬间后腰位置、对手转换推进、中路带球/直塞、后腰拦截与夺回球权、对手禁区内 xGA。
- 适用条件：按 OOP 阵型与实际槽位选择；不可将五后卫专用候选机械套入四后卫站位。

## 3. 边翼卫推进与跨阶段锁位

### 3.1 WB / AWB 推进和传中
- 用户提供的机制判断：门将表现增强后，反击、长传打身后、边路传中（含底线倒三角）是重要破门途径；WB/AWB 的持球推进判定值得优先利用。
- 优先观察：从本方半场推进到进攻三区的带球、推进后的传中/倒三角、远门柱机会、反击和长传形成的射门。
- 验证指标：推进次数/成功率、进入进攻三区次数、传中落点与成功率、倒三角后的射门 xG、远门柱射门、边路失位导致的对手机会。
- 风险：增加传中或推进次数不等于提高机会质量；必须同时检查 xG/射门与对手反击威胁。

### 3.2 有球内收边后卫 + 无球固守型边后卫
- 用户提供的机制判断：若 IP 使用内收型边后卫（Inside Full-Back），而希望 OOP 保持肋部防区，应优先测试无球固守型边后卫（Holding Full-Back）。
- 配套候选：引诱传中（Invite Crosses）。
- 预期收益：有球时形成中路/后腰附近结构，无球时锁住边后卫防区，避免肋部与边路身后空当。
- 验证指标：IP站位与接球区域、OOP回位位置、对手传中数量/质量、边后卫身后被攻击次数、禁区内 xGA。
- 备注：固守型边后卫的逼抢侵略性增强属于用户提供的补丁观察；须在当前原生角色目录中检查固定 PI 和合法指令，不得越权写入角色禁止的 PI。

## 4. 前场角色与补丁后避坑

### 4.1 优先角色候选
- **前场自由人（Free Role）**：优先研究其自由跑位、创造力与无球回防行为；适合测试双前腰或单前腰结构。
- **站桩前锋（Target Man）**：优先研究长传、传中、争顶、支点和二点球衔接；需要检查球员属性和队友跑位是否匹配。
- 两者均为角色候选，不是无条件强制选项；必须按当前原生 catalog 的正式角色名、职责与 PI 权限生成。

### 4.2 降低优先级/默认规避
- **内切型边锋（Inverted Winger）**：用户指出 27.1.0 加强边路无球逼抢后，内切接球转身容易遭遇上抢；降低默认优先级，除非当前阵容/测试证明有收益。
- **中锋“冲击防线（Attack the defensive line）”PI**：用户指出 27.1.0 后仍容易增加越位；默认不启用，专项验证后才考虑。
- 需要与 Inverted Winger 区分：角色名称相近的 Inside Forward / Inside Winger 不可混为同一角色，必须使用游戏原生 catalog 的确切 ID 和名称。

## 5. 全局个人指令：更积极/凶狠抢断（Tackle Harder）

- 用户提供的机制判断：在多个 FM 版本中，个人 Tackle Harder 可能增加夺回球权/球权转换；用户认为 27.1.0 与 27.1.1 对推搡犯规和黄牌判定的调整降低了纪律成本。
- 优先实验：按原生 catalog 权限，在适合的球员位置/角色上扩大 Tackle Harder 覆盖；记录实际生效球员和阶段，不能只记录“全队开启”。
- 核心验证指标：球权转换次数、抢断尝试/成功、抢断后本队控球回合、对手进攻回合、对手 xG/xGA、最终 PPG。
- 纪律数据：犯规、黄牌、红牌可作为副作用背景记录，但依项目当前绩效政策，不作为战术质量评分或版本成败判据。
- 风险：盲目全员叠加可能增加失位、被过、任意球或不必要对抗；须核验角色 PI 权限和位置适用性。

| 优先级 | 研究主题 | 最低验证要求 |

| P0 | 高位遭遇线 + 大幅后撤防线 | OOP实际结构、禁区内 xGA、直塞/身后威胁、主客场拆分 |
