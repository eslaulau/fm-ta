# FM27 外部引擎逆向与战术机制研究｜指定来源库

> 本文件是外部研究来源目录，不是战术配置授权文件。2026-11-27用户固定边界生效后，外部样本只用来研究角色/职责、个人指令PI、非红框团队指令TI及其机制证据。
>
> **本项目研究原则：外部战术不必是四后卫。** 可以研究任何外部阵型以理解其角色行为和引擎机制，但不能将外部IP阵型、OOP位置图、阶段位置转换、心态或红框15项TI移植进本项目。能迁移的只限球员角色/职责、PI和非红框TI；必须落在4-2-3-1、4-3-3、4-1-2-3之一，并保持V0.5 OOP位置映射、心态4和15项红框TI固定。

## 3. 跨阵型机制迁移规则（本项目最重要的新增要求）

**外部战术阵型不是筛选研究资料的门槛；IP四后卫只约束本项目最终生成的战术。**

对每一套有价值的外部战术，无论它是三后卫、四后卫还是五后卫，都要完成以下拆解：

1. **识别原结构**：记录IP与OOP各自阵型、后场人数、位置槽、角色/职责及阶段转换；不能仅凭战术标题判断。
2. **提取机制单元**：逐个提取角色、职责、PI、TI、OI、球员属性/熟练度条件，以及它们之间的组合关系。
3. **区分结构依赖与可迁移机制**：
   - 结构依赖：必须依赖第三中卫、翼卫人数、特定后场人数或特定位置邻接关系才成立的效果；
   - 可能可迁移：单个角色行为、PI/TI触发、跑位/盯防错位、压迫分层、传球/传中目标、阶段转换行为等；
   - 条件迁移：需要把原本的三中卫/五后卫职责重新分配给IP四后卫的DL/DCL/DCR/DR或其他七个位置后才可能成立；
   - 不可迁移：当前引擎/原生权限或四后卫结构无法满足，或机制明显依赖被移除的结构条件。
4. **建立四后卫映射**：说明外部机制在IP四后卫中的落点、需要替代的槽位/行为、保留的行为效果，以及可能产生的空间/防守代价。
5. **形成可证伪假设**：说明“行为错位→引擎可能执行→对手AI响应→收益→PPG路径→失败条件→D5指标”。
6. **本地验证**：只有写入项目配方、通过项目门禁，并在用户本地D4/D5验证后，才可升级为本项目有效机制。

### 迁移判定矩阵

| 判定 | 含义 | 如何处理 |
|---|---|---|
| 可直接迁移 | 机制单元不依赖外部阵型人数/邻接结构 | 作为本项目待测PI/TI/角色候选，不代表已有效 |
| 可重构迁移 | 机制有效性可能依赖结构，但可由四后卫槽位重新分配行为实现 | 设计四后卫等效方案，明确替代关系与风险 |
| 结构依赖 | 机制必须依赖外部三/五后卫特定位置关系 | 不复制结构；研究是否存在四后卫替代机制 |
| 不可迁移 | 违反IP四后卫硬约束或当前build权限/证据排除 | 记录原因，不进入当前配方 |
| 证据不足 | 无原始配置、样本/协议不明或机制因果不清 | 保留线索，不作有效性结论 |

**严禁两种错误：**
- 只收集外部四后卫战术，因而漏掉三后卫/五后卫战术中可迁移的引擎行为错位；
- 因某个三后卫/五后卫战术跑分高，就把其整体结构或成绩当作本项目四后卫方案的证据。

## 5. 证据等级

- **A：受控大样本**——公开协议清楚、样本量充分、build明确、对照条件可复核。
- **B：可复核测试**——有原始配置/截图、样本和结果，但测试控制或独立重复有限。
- **C：社区观察**——有明确描述或玩家案例，但条件不统一、因果不明。
- **D：推测/未核实**——无原始配置、来源不明、仅凭转述或未经验证的机制解释。

证据等级与迁移判定分开记录。A等级的三后卫测试也不意味着其整套战术可迁移到四后卫；C等级的某个PI线索也不应因阵型不同而被忽略。

## 6. 当前研究执行原则

- 优先检索用户指定的八个来源，不再以旧参考网站名单扩展为默认搜索池。
- 每轮按当前FM27 build和具体研究问题检索；不能把27.0.1/27.1.0结果直接当成27.1.1结论。
- 同一网站内部先按相同build、相同协议比较；跨网站协议不同则分表，不合并PPG、Pts/38或样本数。
- 榜单负责发现候选，原始FMF/截图负责解析配置，机制帖负责解释假设，本队D5负责最终验收。
- 任何外部战术即使采用三后卫/五后卫，只要能拆出可迁移的角色/指令/阶段错位，都必须进入研究视野；最终生成仍严格遵守IP四后卫。


## 2026-11-27｜R5.3前五人攻击线与四后卫迁移

### MetaFM 27.1.1 Vanco Hellcat v21
- 页面：https://metafm.net/tactics/vanco-hellcat-v21
- 页面报告：2,240场，PPG 1.93，场均进球2.50，场均xG 2.29，场均失球1.42；IP 4-1-2-3 / OOP 5-2-3。
- 可迁移结构：IP双出球中卫、单防守中场、AMCL ChannelMidfielder A、AMCR SecondStriker A、STL/STR ChannelForward A、ST CentreForward A；OOP由DMC补入第三中卫、两名攻击中场下降为双后腰、三名前锋转换为前场三人。
- 本项目改造：保留IP DL/DCL/DCR/DR四个后场位置槽；将IP DL/DR设计为双组织型翼卫以供宽；OOP形成五后卫/双后腰/三前场。外部页面的PPG/xG不转作本队目标或战术准入证据。
- 项目门槛远高于该样本：本队仍要求完整38场至少109分（PPG≥2.85）且团队xG≥100。
- 证据边界：这是固定AI跑分协议下的外部观察，不是本队存档，也不是单变量实验。角色默认行为、实际跑位和对手AI反应仍需D4/D5验证。

### R5.3指令完整性治理
- 本项目原生TI目录目前有29个可映射组；每轮recipe必须逐组写入，不得让未写入的组从V0.5载体继承可见选择。
- DEFAULT是明确重置操作：生成器清空该组所有非默认native_bit，再保留默认。
- 原生FMF中尚未解码的opaque位仍由V0.5载体保留；不能把opaque位称为一条已识别/已继承的可见球队指令。
