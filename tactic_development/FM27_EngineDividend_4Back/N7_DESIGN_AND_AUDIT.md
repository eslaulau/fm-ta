## 本轮执行规则

本轮按用户新指令，每次必须同步调整前场、中场、后场三个区域。N7以N3为唯一战术父版本；不把N6当父版本。除下列三线调整外，其余IP/OOP槽位全部继承N3。

## 一、三线调整

### 1. 前场：中锋 → 抢点前锋

- IP ST：`CentreForward / A` → `Poacher / A`。
- ST个人指令：保留“更多射门”；移除“后点”指令，避免将抢点角色再固定到单一后点目标。
- 最关键的N6教训：IP ST映射到OOP AMC的高位出口必须保留。本轮OOP AMC继续使用N3的 `SplittingOutletAttackingMidfielder / A`，不改为回防前腰或防守职责。
- AML内锋、AMR边锋、AMC进攻型中场全部保持N3配置。

**待验证假设：** 抢点前锋可能把N3已经创造的机会更集中地转化为禁区内射门；同时保留中央无球出口，避免夺回球权后只有中场接应。

### 2. 中场：右中场 → 前场组织核心（支援）

- IP MCR：`CentralMidfielder / S` → `AdvancedPlaymaker / S`。
- 个人指令改为 `PASSING_RISKS: TAKE_MORE_RISKS`。
- MCL肋部中场进攻职责保持不变。
- OOP DMR边路补位后腰、DML屏障后腰保持N3配置，不改变中场防守槽位映射。

**待验证假设：** 由一名明确的组织核心承担更具穿透性的传球，给中锋、内锋和前腰的纵深跑动提供更直接的输送；MCL继续负责前插，避免两名中场同时改为前插型角色。

### 3. 后场：左后卫 → 边后卫（支援）

- IP DL：`InsideFullBack / D` → `FullBack / S`。
- 清除旧内收边后卫专属的短传、减少冒险传球、减少射门PI。
- OOP DL继续使用N3的 `HoldingFullBack / D`，其余三名后卫的角色和职责均不变。

**待验证假设：** 左侧边后卫在有球阶段提供外侧支援，给内锋内切后的左路留出额外接应点；无球阶段仍回到留守边后卫，避免把有球支援职责直接带入防守阶段。

## 三、四类配置决策

### 继承保留
- N3作为父战术及其真实FMF哈希。
- N3的AMR边锋进攻、AML内锋进攻、AMC进攻型中场进攻。
- N3的双中场OOP屏障、两侧回防边前卫、双中卫分工、四后卫无球留守结构。
- N3的OOP AMC高位分割接应出口。
- N3的29组TI及心态4。

### 替换淘汰
- ST的通用中锋角色改为抢点前锋；删除后点PI，保留更多射门。
- MCR的普通中前卫及“减少冒险传球/更多前插”PI改为前场组织核心支援及“更多冒险传球”。
- DL的内收边后卫防守职责及其三项PI改为边后卫支援。

### 新增待验证
- 抢点前锋能否提高禁区内射门与实际进球，而不损失反击接应。
- 组织核心支援能否提高传入进攻三区、关键传球、绝佳机会和团队xG。
- 左后卫有球支援能否改善左侧接应/传中后射门，同时不抬高对手反击、xGA和失球。
- 三个区域组合后的整体结果是否优于N3的77分、90:34、xG75.62、xGA42.86。

### 证据不足
- N3与N7并非同一存档/同种子受控A/B；N7整季差异只能证明组合表现，不能单项归因。
- Exporter未必能把球员位置码完整映射回IP/OOP角色；角色级归因必须按可识别覆盖率降级。
- Poacher、AdvancedPlaymaker和FullBack的角色默认行为不等于本轮所写显式PI；本轮只声明原生目录允许的配方，不臆造角色自带行为细节。
- D1-D3只证明角色/PI权限与FMF格式正确；不代表游戏内导入或比赛效果通过。
