# FM27 EngineDividend 4Back｜现行项目规则

本文件是唯一总规则。专项边界、研发流程、构建流程分别见：
- 固定边界：`TACTIC_FIXED_CONSTRAINTS.md`
- 研发流程：`UPGRADE_GATE.md`
- 构建流程：`GENERATION_EXECUTION_POLICY.md`
- 历史配置与证据：`TACTIC_INSTRUCTION_DECISION_LEDGER.md`
- 版本与产物索引：`VERSION_CATALOG.md`

## 项目目标
研发利用 FM27 比赛引擎机制的有球四后卫战术，不以现实足球合理性限制设计。当前目标为完整38场联赛至少100分且至少100个进球；xG作为进攻过程诊断指标，不替代实际进球和积分。没有完整赛季证据不得宣称达标。

## 不可违反的现行要求
1. 严格遵守 `TACTIC_FIXED_CONSTRAINTS.md`：IP只允许4-2-3-1、4-3-3、4-1-2-3；OOP位置映射、心态4和15项红框TI固定；仅调整角色/职责、PI和14项非红框TI。
2. 战术研究只使用本项目内部历史资料和用户提供/确认的实测数据；不搜索、不引入外部战术、外部战术排名或外部战术配方。
3. 不强制从V0.5重新开始。每轮明确实际父版本、父FMF及SHA-256；V0.5可作为二进制序列化载体，但不自动成为战术父版。
4. 每轮设计必须记录四类决策：继承保留、替换淘汰、新增待验证、证据不足。不得将结构性继承表述为效果已验证。
5. 赛季分析必须使用用户确认的实际战术版本；不得由导出器自行猜测每场使用的战术。缺失数据明确标注，不得补造。
6. 不存在D0设计审批、D0机器清单或D0构建阻断。不得恢复旧验证器或以旧模板未填写阻止构建。
7. 原生权限预检、结构检查、FMF生成和独立回读是必要技术步骤；D4游戏内导入、D5比赛/赛季效果分别记录，不能混为一谈。
8. 不静默修改用户指定配置，不覆盖历史产物，不宣称未经实测的效果。

## 证据与状态
- D1：原生位置、角色、职责、PI权限预检。
- D2：配方结构与固定边界核验。
- D3：FMF生成、独立回读及同次报告核验。
- D4：游戏内导入和显示验证。
- D5：比赛/完整赛季表现验证。
D1-D3通过只证明文件构建技术正确，不证明战术有效。
