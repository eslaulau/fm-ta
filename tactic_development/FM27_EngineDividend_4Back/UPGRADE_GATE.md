# FM27 EngineDividend 4Back｜现行研发流程

本文件描述实际工作顺序，不设审批门禁。用户提供新赛季报告或要求新战术时，按以下流程直接推进。

1. **确认输入**：确认赛季报告、Exporter run、FM27 build、用户指定战术版本及该版本FMF/recipe。不得自行推断每场实际使用的战术。
2. **诊断结果**：分析积分、进球/xG、失球/xGA、机会质量、胜平负差异、主客场和关键比赛；数据覆盖不足时注明。
3. **位置与配置分析**：逐位置检查IP/OOP角色、职责、PI和整体结构的收益与代价；不得仅凭单项评分作因果结论。
4. **查阅内部历史**：读取 `TACTIC_INSTRUCTION_DECISION_LEDGER.md` 和 `VERSION_CATALOG.md`，选择实际父版本/配置组件，比较历史表现与当前问题。禁止外部战术研究。
5. **设计新版本**：严格遵守 `TACTIC_FIXED_CONSTRAINTS.md`；形成完整11槽、22阶段配置，并明确四类决策：继承保留、替换淘汰、新增待验证、证据不足。
6. **构建交付**：按 `GENERATION_EXECUTION_POLICY.md` 完成原生预检、结构核验、FMF生成和独立回读；交付FMF及同次report。
7. **验证与回写**：D4由用户在游戏内确认；D5按真实比赛/完整赛季报告分析。将版本身份、结果、证据边界和四类决策写回历史总账与版本目录。
8. **继续迭代**：D5报告分析及总账回写完成后，按用户授权继续下一轮设计；遇到真实技术阻断才暂停，并说明具体错误和未完成步骤。

本流程不是D0门禁。分析记录、审计模板或历史表格未填写，不得单独阻断原生构建。
