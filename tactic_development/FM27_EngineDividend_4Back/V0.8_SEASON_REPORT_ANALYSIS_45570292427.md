## 整体诊断

1. **V0.8 的进攻骨架有效恢复。** 与 V0.7 相比，射门、射正、xG、进攻三区进入、控球率同步改善；不应把 MCR 稳定接应、AMC 进攻前插、双侧组织型边锋和高节奏/窄宽度组合推倒重来。
2. **非胜场得分转化是更直接的薄弱点。** 平局和败场的机会质量并不低，ST 位置产量明显低于 xG；需要优先审查中锋攻击路线与禁区终结，而非再对全队叠加更多进攻指令。
3. **客场推进仍是第二问题。** 客场进攻三区传球显著少于主场，对手进入进攻三区更多；本轮先不动后场四人和双中场，避免同时引入另一套变量。
4. **数据限制明确。** 目标 build 未在 fmsave 0.14.3 上游登记；两场比分各有一球尚未归属；身份与 role_code 覆盖仍有缺口。上述不会改变已核验的球队位置统计，但球员和角色级结论只对实际识别样本有效。

## V0.8 → V0.9 设计决定

本轮采用针对终结环节的角色包调整：

| 配置 | V0.8 | V0.9 |
|---|---|---|
| IP ST 角色 | 拉边前锋 | 抢点前锋 |
| 职责 | 进攻 | 进攻 |
| 更多射门 | 保留 | 保留 |
| 禁区攻击方向 | 后点 | 后点 |
| 更多前插 | 更多前插 | 不再显式设置；原生角色目录不提供此 PI |
| 球队指令 | V0.8 原值 | 全部不变 |
| 其他 10 个位置及全部 OOP | V0.8 原值 | 全部不变 |

设计逻辑：保留 V0.8 的团队创造和中路支持，不再让 ST 额外承担拉边/额外前插任务，尝试将接应终点集中到禁区和后点。Poacher/Attack 在原生 catalog 中可用；更多射门与后点攻击两项 PI 均可写入；更多前插在该角色下不提供，因此没有伪造或静默写入。

这是数据驱动的整套结构审查后针对单一明确瓶颈的角色重构，不是把“单变量 A/B”设成项目目标。预期收益是改善中锋的禁区到位与 xG 转化；风险是减少拉边接应、让前场横向牵制变弱，或降低中锋参与串联的频率。下一轮必须同时检查团队 xG、禁区机会、ST 球数/xG 差额、越位、平局/败场和客场推进，不能只看中锋进球。

## 结论

V0.8 是相对 V0.7 的明显反弹，并把 V0.6 的联赛水平基本找回。V0.9 因此不改有球四后卫、团队指令、中场、AMC 或 OOP，而只把 ST 从拉边前锋（进攻）改为抢点前锋（进攻），保留射门与后点 PI。V0.9 比赛效果待下一份赛季报告验证。
