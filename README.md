# FM27 战术生成规则

本目录采用唯一正式流程：战术设计 → 原生兼容核对 → GEN1 中间配方 → 离线原生 FMF 生成 → 独立回读 → 游戏内验收。正常的“生成新战术”请求，最终交付物必须是 FM27 原生 .fmf 文件；GEN1 不是成品。

| 阶段 | 目录 | 职责 |
|---|---|---|
| 02 原生规则 | [02_FM27原生权限规则](02_FM27原生权限规则/README.md) | 提供原生位置、角色与 PI 权限资料，供设计和独立预检使用 |
| 03 GEN1 | [03_GEN1编码与导入规则](03_GEN1编码与导入规则/README.md) | 生成完整的 FM27GEN1 v1 中间配方 |
| 04 离线生成 | [04_离线原生FMF生成器](04_离线原生FMF生成器/README.md) | 使用本地 Python 源码、FMF 模板和 catalog 生成原生 FMF |

## 默认交付合同（必须执行）

用户提出“生成新战术”“做一套战术”“优化后给我战术”等请求时，默认交付：

1. **必交：** 本次实际生成的原生 .fmf 文件。
2. **必交：** 与该 FMF 同次生成的 .report.json 独立回读报告。
3. **辅助留档：** 对应 GEN1 TXT 可一并提供，便于复现和审计；它不能代替 FMF。
4. **说明：** 简要列出阵型、战术设计要点、数据依据及尚未验证的限制。

只生成 GEN1、展示 Base64、给出运行命令或描述战术设计，均不算完成战术生成。若生成器没有实际成功运行，必须明确报告失败/阻塞原因，不得用 GEN1 冒充 FMF，也不得声称已经得到可导入文件。

## 唯一正式生成流程

1. **读取与分析。** 按用户目标读取最新适用的球队、球员、位置和比赛数据；确认样本范围、数据缺失及存档分支限制。
2. **战术设计。** 确定 IP/OOP 阵型、11 个槽位、各阶段角色、PI 和球队战术意图。
3. **原生兼容核对。** 使用第 02 层资料核对位置、角色、phase、duty 与每一条 PI。当前生成器只自动检查角色/位置/phase 兼容性和有限 PI 白名单，不会自动执行完整 PI 权限 CSV 的逐项裁定；无法证明的项目必须标记为未验证。
4. **生成并预检 GEN1。** 输出 v1、11 槽位、每槽 in/out 阶段、位置、角色、PI 和 TI 配方；验证 Base64/JSON、字段、唯一位置、角色映射与白名单。GEN1 只作为下一步输入。
5. **实际生成 FMF。** 必须调用第 04 层离线生成器，传入本次 GEN1 TXT、FM27 source-major 27 原生模板、catalog，以及本次独立命名的 FMF 输出路径和报告路径。
6. **独立回读。** 检查生成器返回码、FMF 文件确实存在且非空、报告确实存在；确认报告中的 FMF/TAC 容器、11 组 IP/OOP、22 阶段位置/角色/PI mask、TI 向量和成员长度/解压检查通过。任何失败都不能标记 D3。
7. **交付。** 向用户提供本次实际生成的 .fmf、对应 .report.json，以及可选 GEN1 TXT。不可只粘贴 GEN1 代码。
8. **游戏内验收。** 在 FM27 导入该 FMF，检查阵型、角色、PI、TI 和职责，保存后关闭并重新打开。只有此步骤通过才是 D4/游戏内可用。
9. **实战验证。** D4 后才进行统一条件的比赛样本测试。结构回读、游戏内载入和比赛表现是不同等级的证据。

详细操作以 [离线生成流程](04_离线原生FMF生成器/FM27GEN1_离线原生FMF_生成流程.md) 和 [字段契约](04_离线原生FMF生成器/FM27GEN1_离线原生FMF_字段契约.md) 为准。

## 当前生成器的明确限制

- GEN1 v1、11 个槽位；仅实现 Gegenpress 风格。
- 必须使用 FM27 source-major 27 模板；需要原生 `.tac/.aom/.img` 成员。
- PI/TI 采用源码有限白名单；未知值会报错，不会静默忽略。
- duty 由源码 `ROLE_DUTY` 固定映射，并非 GEN1 明确字段。
- OOP 的 STC 会在写入时规范化为 ST。
- 完整 PI 权限矩阵没有被当前生成器自动逐项执行；权限资料须单独核对。
- TI 为单一 12 字节向量，从模板继承未在 GEN1 中明确出现的 key。

**不得把“二进制结构回读通过”描述成“所有 PI 权限已验证”或“比赛效果通过”。**

## 现有战术主动优化规则（必须执行）

当用户提供现有战术及其比赛、球员或位置表现数据，并要求优化时，必须进行**主动优化**，不能只做分析、评价或提出建议。目标是根据真实数据找出战术弱点并直接改进，最终必须按本目录流程生成原生 .fmf，并交付对应独立回读报告。

### 一、逐位置评估当前角色是否合理

必须依据各位置的实际表现数据进行判断，至少检查数据中可用的以下指标：

- 平均评分、低分场次及低分比例；
- 进球、助攻及参与进球表现；
- 抢断、拦截、夺回球权等防守数据；
- 传中、关键传球、创造机会等进攻数据；
- 其他能够反映该位置职责完成情况的数据。

不能只按球员总评分或单项数据机械判断。必须结合该位置在当前阵型中的任务、IP/OOP 阶段职责、球队整体打法以及数据样本量，判断当前角色是否适合。

### 二、保留优势位置，优先修复弱势位置

- **表现优秀的位置：**保留有效角色与指令；有明确数据依据时才进一步强化，不得为了追求变化而随意改动。
- **表现较差的位置：**必须主动考虑更换更合适的有球角色（IP）和无球角色（OOP），不能只写“建议调整”而不落实修改。
- **优先级：**先解决数据反复暴露、影响整体攻防的弱势位置，再处理次要优化项。
- 每项改动都必须说明对应的数据问题、战术原因和预期改善方向。

### 三、同步优化球员个人指令

针对每个被调整的位置，必须同步检查并优化：

- 有球球员指令（IP Player Instructions）；
- 无球球员指令（OOP Player Instructions）。

个人指令必须与对应阶段的角色、位置和整体战术意图一致，并通过第 2 层原生权限规则核验。不得输出该位置或该角色不支持的指令；不得把权限查询别名当作已经验证的游戏内原生位置或角色。

### 四、根据整体表现优化球队指令

必须结合球队整体攻防数据检查球队指令和整体战术意图。当前 FMF 生成器只写入单一共享的 12 字节 TI 向量，不存在独立 IP/OOP 两套 TI 向量；只能写入源码白名单支持的选项。不能把设计分析中的 IP/OOP 差异伪装成两套已实现的指令，也不能仅凭主观偏好整体替换指令。

### 五、最终必须交付原生 FMF

完成分析和修改后，必须实际运行第 04 层离线生成器，并直接交付：

1. 新生成的原生 .fmf 战术文件；
2. 与该 FMF 同次生成的 .report.json 独立回读报告；
3. 可选的完整 GEN1 TXT 源配方，供审计和复现；
4. 简要数据依据与改动说明，逐项说明重点弱势位置的问题、角色或指令如何改变，以及保留优秀位置的原因。

GEN1 正文、改动清单或建议都不能代替 .fmf。若生成器未成功运行，必须如实标明任务未完成及具体阻塞原因。

### 六、数据真实性与权限约束

- 所有改动必须能追溯到用户提供的比赛或球员数据，以及本资料库中的规则依据；不得虚构评分、统计数据或比赛表现。
- 缺少某项指标时，明确标注数据缺失，不得用推测值补齐；仍应利用现有有效数据完成可行的优化。
- 样本量不足时说明判断置信度，避免把偶然表现当作稳定规律。
- 角色、位置、球员指令和球队指令必须符合 FM27 原生权限及 GEN1 导入规则。
- 若某项理想改动无法通过权限或导入验证，必须选择可验证的兼容替代方案，并说明原因，不得把未经验证的配置伪装成可用配置。
- 不得因优化而遗漏完整阵型、任一位置的 IP/OOP 角色，或当前生成器实际支持并写入的 TI/PI；不得把未实现的独立 IP/OOP TI 写成已完成。

**执行底线：有数据依据地完成设计、实际生成原生 FMF、提供回读报告。只分析、只输出 GEN1 或只给运行命令，均视为未完成。**

## 当前已知的重要限制

- GEN1 v1 无独立 duty 字段；当前源码按 ROLE_DUTY 固定映射，其中 Box-to-Box Midfielder 的 Support duty 有推断成分。
- 当前生成器会将 OOP 的 STC 输入规范化为 native ST selector；须在输出与游戏内验收时确认。
- A9.0.2 样本已通过离线结构回读，用户确认该文件在 FM27 内成功载入阵型；不能外推为所有 PI/TI、模板和比赛效果均已验收。
- 原 A9.0.2 配方中三个持球后腰的 PI 数组本来为空，生成空 PI 是忠实转换，不是漏写。

## 验收等级与证据优先级

- D0：战术设计完成。
- D1：原生角色、位置、duty 与 PI 静态权限核对完成；未知项单独标注。
- D2：GEN1 Base64/JSON 与 11 槽结构预检通过。
- D3：本次原生 FMF 已实际生成，离线 FMF/TAC 容器和源码覆盖范围内的位置、角色、duty、TI、PI 独立回读通过。
- D4：FM27 内加载、核对、保存、关闭并重新打开均正确。
- D5：统一测试条件下完成比赛验证。

正常战术生成任务至少完成 D3。只有 D4 才能称“游戏内可用”；只有 D5 才能评价实战效果。

证据优先级：FM27 内成功加载、保存并重新打开 > 离线生成器独立回读报告 > 原生位置/角色/PI 权限数据 > GEN1 配方与设计依据 > 纯推断。

原始权限 CSV、原始 FMF 样本、GEN1 样本和生成器报告必须保留。所有派生数据都标明来源，不能与原生采集数据混为一谈。
