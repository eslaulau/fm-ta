# 03｜GEN1 配方编码规则

> 统一资料入口：先阅读上级 [00_资料总索引与检索规范](../00_资料总索引与检索规范.md)。当前分支由 04 层 style registry 登记十种官方风格；不要依据历史配方或旧版文档将其误限为单一风格。

本层负责将完成设计与原生权限检查的战术转为标准化 FM27GEN1 配方。GEN1 是中间配方，不是 FM27 原生战术文件；正式 .fmf 生成由下一层离线原生生成器负责。

## 全仓库战术使用政策（必须遵守）

本仓库内所有 GEN1 战术配方、示例编码、历史版本及其对应文件，均为格式/编码/导入流程资料，**不是推荐战术、不是成功战术，也不得作为新战术开发参考**。不得从中复制或改造阵型、IP/OOP 角色、职责、PI、TI 或整体战术结构。GEN1 字段和编码资料只用于理解格式契约、校验输入和生成新配方；新战术配置必须根据用户当前目标与明确限制独立设计，除非用户明确要求，否则不要求真实比赛数据。

## 战术创新原则（必须积极执行）

上述禁止复制和改造仓库现存战术的规则，目的是消除路径依赖，**不是限制创新**。本项目必须积极鼓励原创战术设计：

- 从用户当前目标和明确限制出发，从零提出战术解法；只有用户明确要求时才结合球队球员特点、比赛数据或对手问题；不得先挑一个旧战术再做局部修改。
- 鼓励探索全新的攻防结构，包括但不限于非对称 IP/OOP 阵型、不同阶段的角色与职责重组、全新的 PI/TI 协同、压迫与回撤结构、攻防转换方式，以及不依赖单一传统风格的混合思路。
- 不受仓库现有战术文件、90 条网站预设、历史配方、模板或十种风格名称的战术思路限制。十种风格及其 style code 只是目前掌握的原生文件身份/格式兼容资料，不是必须遵循的战术蓝图，也不代表只有这十种战术思路才可创新。
- 如果当前 FMF 生成链路要求选择已登记的原生 style code 或技术模板，只能把它们作为文件序列化和兼容性载体；实际阵型、角色、职责、PI、TI 与整体攻防逻辑仍须独立原创，不能继承模板原有战术配置。
- 创新方案必须符合 FM27 当前可验证的位置、角色、职责、PI/TI 写入权限和文件格式约束。超出现有映射的想法应明确标记为待研究/待实现，不得静默降级或假装已经支持；超出现有映射的想法必须明确标记为待研究/待实现，不得伪装支持，也不得静默降级。

**研发方向：不寻找旧战术的改良版，而是提出新的战术解法；项目验收以原生 FMF 的 D3 生成和独立回读为终点。**

- **GEN1_导入验收清单.md**：用于历史 GEN1 配方结构检查和原生 FMF 离线生成/回读验收。
- **04_离线原生FMF生成器/FM27GEN1_离线原生FMF_生成流程.md**：当前正式生成流程。
- **04_离线原生FMF生成器/FM27GEN1_离线原生FMF_字段契约.md**：当前字段与阶段接口契约。

## 2. GEN1 v1 数据结构

根对象字段：v、name、ment、base、ti、p。

- v：格式版本。
- name：战术名。
- ment：心态编号。
- base：设计来源、风格、IP 阵型和 OOP 阵型元数据。
- ti：球队指令键值对象。
- p：11 个战术槽位，每槽有 in、out 两个阶段记录；阶段记录包含 pos、role、pi。

编码形式为 FM27GEN1: 前缀加 Base64 JSON。槽位顺序必须按目标阵型对应的槽位映射，禁止把某个 A4.x/A9.x 阵型的固定槽位顺序误用到其他阵型。

## 3. 必须执行的 GEN1 预检

1. 严格识别前缀并校验 Base64。
2. UTF-8 解码并解析 JSON。
3. 核对根字段、心态、base 和 TI 类型。
4. 核对正好 11 个槽位；每槽有 IP/OOP 阶段对象。
5. 每阶段核对位置、角色和 PI 数组。
6. 每个 PI 必须是准确的 [setting, value] 二元组，禁止重复键冲突。
7. 重新 Base64 编码并与原始代码逐字符对照。
8. 预检通过后才允许进入原生权限阶段与离线生成器。

## 4. 正式生成出口

GEN1 通过预检与 FM27 原生权限检查后，交由：

../04_离线原生FMF生成器/FM27GEN1_离线原生FMF_生成流程.md

由离线生成器读取与当前 FM27 格式匹配的原生 FMF 模板，映射战术字段、重建 FMF 容器，并进行独立二进制回读。整个过程在本地完成，不依赖在线服务。

## 5. 验收等级

- D0：原创战术设计完成。
- D1：原生角色、位置、duty 与 PI 权限核对通过。
- D2：结构化配方与 11 槽、22 阶段结构预检通过。
- D3：原生 FMF/TAC 容器及位置、角色、duty、TI、PI 独立回读完整通过；同次报告与实际 FMF 的长度和 SHA-256 一致，artifact 已取回并交付。

**D3 是本项目唯一最终验收终点。** D3 通过并交付 FMF 与报告，战术生成任务即完成；不设置后续游戏内或比赛测试阶段。
