# 02｜FM27 原生权限规则

> 统一资料入口：先阅读上级 [00_资料总索引与检索规范](../00_资料总索引与检索规范.md)。角色显示名称索引在 01 层；本层提供原生内部角色 ID、位置/职责及 PI 权限，两者不是互相缺失。

本层负责回答：某阶段、某位置、某角色和某 duty 状态下，原生菜单允许哪些球员指令。它是生成前的静态兼容过滤依据，不能代替离线生成器回读和 FM27 游戏内验收。

## 1. 资料与数据口径
- 原始角色权限：24 个原生角色菜单位置上下文。
- 不同阶段角色 ID：79 个，其中 IP 40 个、OOP 39 个。
- 原始权限 CSV：1,547 条数据记录；每个角色/位置/阶段组合记录 7 个 duty 状态。
- 角色汇总目录：231 个角色/位置/阶段组合。
- STC 扩展权限表：从原始 ST 位置复制 42 条 IP 与 28 条 OOP 记录，另加 70 条 STC 派生记录；扩展后 1,617 条数据记录。

## 2. 原生采集与派生数据必须分开
- **FM27_Role_PI_Permissions_Original.csv** 保留原始 24 个上下文，不改写。
- **FM27_Role_PI_Permissions_Expanded_STC.csv** 在原始记录后追加 STC 派生记录。只把位置列 ST 改为 STC，其余字段保持一致。
- STC 扩展是查询别名的数据复制，不是重新从游戏 STC 菜单采集的原生权限证据。
- 汇总角色目录包含 231 个组合，其中 STC 的 10 个组合来自别名扩展。

## 3. STC 位置别名：仅用于静态权限查询
项目 GEN1 中央中锋战术槽位使用 STC，而原始权限提取中的中央中锋菜单上下文为 ST。因此静态权限查询使用：

`STC → ST`

这只解决本项目查询表中的位置上下文映射；最终 FMF 仍须按游戏原生位置 selector 写入。

## 4. 其他位置类别边界
- SW、DM 不是本次原生角色权限表中的独立角色菜单上下文，不应为其伪造权限。
- DMC、DMR、DML 是具体防守中场权限上下文；不能因为通用熟练度代码为 DM，就把 DMC 权限任意复制给 DM。
- DC、DCR、DCL、DR、DL、WBR、WBL 等位置需分别查表，不得根据名称近似合并权限。
- 注意：角色槽位权限表只检查位置层级；边中卫、套上中卫及无球边中卫系列还受“三中卫外侧位置”阵型条件限制。四后卫只有 DCL+DCR 两名中卫时不可选这些角色，构建前必须做阵型级检查。
- 角色显示名称、GEN1 role 字符串、权限表内部角色 ID 和位置代码是不同字段，必须通过映射表关联，不能模糊匹配。

## 5. 权限检查顺序
1. 确认阶段：IP 或 OOP。
2. 确认该阶段的目标位置代码。
3. 通过 Position_Code_Crosswalk 解析原生权限查询上下文。
4. 查询准确内部角色 ID 和该阶段的 duty 状态。
5. 对计划使用的每一条 PI 检查可编辑项、固定开启项和固定关闭项。
6. 将静态权限结论与离线生成器回读、游戏内导入结果分开记录；发生运行时拒绝时，不要用静态表强行判定成功。
